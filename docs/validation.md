## 发现并处理的兼容边界

网页恢复采集时曾只同步设备的 LITE 档位，输入仍保留 FULL 的 2 FPS/10 Hz；固件会拒绝超过 LITE 1 FPS/1 Hz 的参数。现同步实际档位和频率，输入上限与发送前校验均随档位变化。暂停快照明确显示“采集已暂停”，屏幕旁可直接开启；其他遥测更新不会重置 OLED 帧龄。回放在暂停时保留档位，与实机一致。

修复后的实机验证通过网页从 LITE 正常开启，再切换 FULL。观察到 9 个不同秒数的 OLED 帧、2 组资源样本、8 个状态样本，可用堆 38,880–70,944 字节，设备 bootId 未变、未重启，时间误差估计仍在目标内。该次验证结束保持 FULL 会话开启，使用当时未自动续期的 600 秒会话；该次未修改或上传固件。后续自动续期验证见下文。

## 二进制 USB 输入与定制构建准备

- 官方文本流 `read(1)` 按 Unicode 字符补读；poll 只保证首字节就绪，残缺 UTF-8 因而存在阻塞整个循环的风险。改为 `sys.stdin.buffer` 每次只读一个已就绪字节，完整行后严格解码；错误 poll 事件不读，保留 8192 字节帧限制和每 tick 512 字节预算。无二进制接口的端口明确禁用该调试输入，不回退到有风险的文本读取。这个机制风险已消除，但没有捕获旧现场触发字节，不能据此认定所有历史停更同因。
- 正常启动的独立实机测试观察 20 秒：开启命令和随后快照均收到匹配 ACK，14 个不同秒数、14 个状态和 4 组资源指标；故意发送单个 `0xC2` 后等待四秒期间仍出现 3 个不同秒数，补换行后继续出现 8 个秒数，无运行步骤异常。结束后 bridge 的 FULL 与新状态均确认。初次独立脚本遗漏协议前缀的失败记录保留作废，未计为设备停更。
- 定制 1.29 构建已离线完成：固定上游 MicroPython / ESP-IDF 版本，冻结 20 个公开应用模块及独立构建标记，不冻结 `boot.py` 或私有配置；保留默认冻结标准库。动态 TLS 缓冲启用、DTLS 关闭，CA / 配置不动态释放，时间验证保留，RX / TX 上限仍为 16384 / 4096 字节。应用镜像 1796864 字节，原 factory 分区余量 234752 字节，分区定义与官方 1.29 一致；尚未将离线编译当作实机通过。
- Windows 的长命令、GCC 响应文件引号和 shell 流水线适配仅发生于宿主构建流程，完整 patch / helper / 工具哈希保留；不改变目标运行 C 源码或放宽安全选项。镜像版本字符串包含 `v1.29.0-dirty`，应标为定制构建，而非官方原版二进制。实机标准 1.29 未提供 `machine.bootloader()`，仍需人工 BOOT / EN，不能按泛化的系列资料假定此接口存在。

## MQTT / RS485 配置与 SHT20 校验准备（2026-10-31）

## 原生调用、链路与精度边界

Windows 的 SerialPort 13 原生绑定在 Node.js 26.4+ 可能停滞 Promise / nextTick 回调，参见上游 [bindings-cpp #243](https://github.com/serialport/bindings-cpp/pull/243)。本机 A/B：没有唤醒任务时 3 秒后 write callback 未完成；20ms 唤醒后 callback 返回且收到 9,797 字节。当前仅在受影响 Windows 串口打开期间启用 unref 唤醒任务，关闭清理。保留 Node 26 LTS，没有切换系统默认 Node。

ESP32 UART0 接收环形缓冲小，设备发送 OLED 时会同步占用时间。Host 命令按 UTF-8 每片最多 64 字节、间隔 60ms 完整串行发送；固件每 tick 最多一帧，避免大表单或并发命令互相交错及丢字节。这一限制与 Node 版本无关。

同步 DNS 仍可能暂时延迟 USB；TCP 和 NTP 均缓存解析结果、非阻塞轮询，debug 开启也会继续校时。500ms 为依据所选服务器与网络样本的条件估计目标；断网、路径不对称或突变温漂仍可能超出，状态会显示当前与下次校时前的预算。初始漂移采用保守假设，再由至少间隔 60 秒的样本估计，校准间隔限制在 30–300 秒。未知 GPIO 没有电气测量，输出白名单为空。温湿度已具备临时读取及短时持续上报证据，本机受控重连已短测通过，服务端踢线后的恢复和长期稳定性仍未通过；本期没有云部署、MQTT 远程调试或下游存储验收。

可选实机检查：本地 bridge 运行后执行 `node tools/hardware-smoke.mjs`。它会开启短期 debug、按原值保存完整配置（revision 加一），验证多帧时钟变化后关闭 debug；加 `--wifi-rollback` 测试不可达 SSID 试用回退，`--minute-probe` 核对两次 TCP 发起间隔，`--clock-sync` 等待第二次独立 NTP 响应并检查校正前偏差加不确定度是否在 500ms 内，`--metrics` 检查一分钟资源采样、LITE 周期与关闭后停止。它不是 CI 测试，执行前须关闭所有已打开调试页面的自动续期，否则短期 TTL 会被其他页面延长。执行时独占设备控制，不要同时操作网页或上传。

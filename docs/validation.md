- 固件上传后正常连接原 Wi-Fi、同步 NTP、完成 TCP 测试，传感器始终禁用。

- 不可达 SSID 的 60 秒试连返回 rolled-back，原配置 revision 不变，并恢复原网络连接。USB 在试连和离线过程中继续提供状态、屏幕和命令回执。

- 最终固件与 bridge 再次实机检查通过：21 个状态样本、3 个 OLED 帧、完整配置保存、自动到期和关闭，无坏帧告警或异常重启；可用堆内存 41,328–102,720 字节。
- 当前 USB→TTL 链路曾出现坏帧，保留告警并有界重取快照（2 秒冷却、每连接最多 3 次）；不自动重发配置或重启操作。Host 回归覆盖 28 项残缺引脚状态经恢复重新变为 34 项。
- 时钟与分钟探测后续实测：FULL debug 下收到 68 个秒数不同的 OLED 帧、71 个状态样本；TCP 发起 uptime 为 4,317 和 64,365ms，间隔 60,048ms，成功连接目标。可用堆内存 39,792–98,304 字节；出现 3 次可恢复坏帧告警，最终 34 项引脚完整且没有异常重启。验证后 debug 正常关闭。
- 时钟改为先计算整数时区偏移，再与整数 epoch 相加，避免 ESP32 float32 把当前时间量化成约 64 秒步长。非阻塞 TCP 的完成确认兼容 ESP32 未导出的 newlib `EISCONN=127`；该值已通过真实设备调用确认。
- 高精度 SNTP 实测：首次校时修正旧整秒接口留下的约 581ms 偏差；相隔至少 60 秒的第二次响应测得校正前偏差 -7.556ms、样本不确定度 39ms，合计 46.556ms。自适应周期调整到约 252 秒；该测量使用独立响应的校正前偏差，而非写完 RTC 后的零偏差。
- 独立只读对照：暂停应用后通过 `time.time_ns()` 取得真实 RTC，另发三个 UDP NTP 请求，不调用 ClockSync 或写入 RTC。偏差分别 -1.315 / +2.502 / -0.387ms，加网络不确定度后的上界估计 34.016 / 37.371 / 37.008ms。测量文件留在被 Git 忽略的本机设备备份目录。
- 最终冻结 ClockSync 的第二次校时前偏差为 +1.450ms，不确定度 40ms；下一周期约 262 秒，TCP 两次探测继续保持一分钟。坏串口片曾使同次启动的引脚刷新只剩 28 项，现快照片全部增量合并并保留已知记录；负对照回归准确复现旧问题，修复后保持 34 项。
- 对冻结组件再次独立只读复核：偏差 +3.786 / +1.097 / -2.257ms，含网络不确定度的估计上界 44.157 / 36.271 / 37.773ms，均小于 500ms。该对照不写 RTC，并已核对设备模块 SHA-256 与最终源码一致。

## 发现并处理的兼容边界

Windows 的 SerialPort 13 原生绑定在 Node.js 26.4+ 可能停滞 Promise / nextTick 回调，参见上游 [bindings-cpp #243](https://github.com/serialport/bindings-cpp/pull/243)。本机 A/B：没有唤醒任务时 3 秒后 write callback 未完成；20ms 唤醒后 callback 返回且收到 9,797 字节。当前仅在受影响 Windows 串口打开期间启用 unref 唤醒任务，关闭清理。保留 Node 26 LTS，没有切换系统默认 Node。

ESP32 UART0 接收环形缓冲小，设备发送 OLED 时会同步占用时间。Host 命令按 UTF-8 每片最多 64 字节、间隔 60ms 完整串行发送；固件每 tick 最多一帧，避免大表单或并发命令互相交错及丢字节。这一限制与 Node 版本无关。

同步 DNS 仍可能暂时延迟 USB；TCP 和 NTP 均缓存解析结果、非阻塞轮询，debug 开启也会继续校时。500ms 为依据所选服务器与网络样本的条件估计目标；断网、路径不对称或突变温漂仍可能超出，状态会显示当前与下次校时前的预算。初始漂移采用保守假设，再由至少间隔 60 秒的样本估计，校准间隔限制在 30–300 秒。未知 GPIO 没有电气测量，输出白名单为空。构建主包约 610KB / gzip 195KB；本期没有云部署、MQTT 实机验证或温湿度采集。

可选实机检查：本地 bridge 运行后执行 `node tools/hardware-smoke.mjs`。它会开启短期 debug、按原值保存完整配置（revision 加一），验证多帧时钟变化后关闭 debug；加 `--wifi-rollback` 测试不可达 SSID 试用回退，`--minute-probe` 核对两次 TCP 发起间隔，`--clock-sync` 等待第二次独立 NTP 响应并检查校正前偏差加不确定度是否在 500ms 内。它不是 CI 测试，执行时独占设备控制，不要同时操作网页或上传。
